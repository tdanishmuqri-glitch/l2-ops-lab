| | |
|---|---|
| Incident | INC-0001 (P1) |
| Problem | PRB-0001 |
| Duration | 11 minutes (09:58–10:09) |
| Impact | 100% of `/verify` requests failed in all markets; ~11 min gap in analytics events |
| Detection | Prometheus `DatabaseDown` alert (1 min) + L1 customer calls |
| Author | T. Danish, Digital Operations L2 |

## Root cause — 5 Whys
1. **Why did verifications fail?** The app could not connect to PostgreSQL.
2. **Why?** Release 1.2.0 used a wrong database password.
3. **Why did a wrong password ship?** The credential was edited in the release config instead of being read from the secret store.
4. **Why wasn't it caught before production?** Smoke tests ran *after* traffic was switched, not before.
5. **Why?** The deployment had no readiness gate — new pods received traffic before `/health` confirmed DB connectivity.

**Root cause:** no pre-traffic health gate + credentials managed outside the secret store.

## What went well
- Alert fired within 1 minute; runbook RB-05 made rollback a 2-minute action.
- Request IDs and structured logs gave a definitive error message immediately.

## What went poorly
- Customers noticed before the alert was acknowledged (4-min ack time).
- Analytics team was not in the notification path.

## Corrective & preventive actions
